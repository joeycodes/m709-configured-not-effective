### note: the SP's own activity -- the IMDS token request and the ARM resources-list GETs in (a), (b), (c) -- produces NO AzureActivity row (first query empty). AzureActivity records control-plane WRITES; a read and a token acquisition are not writes. The only visible events are the operator's own role assign/remove (second query, Caller = <owner-id>), which are the misconfiguration and its cleanup, not the attack. So the credential theft and the read are invisible; only granting the role leaves a trace, and only if someone watches role-assignment writes. These operator writes serve as a control group: a write by the same window IS logged, which is why the read's absence is meaningful rather than a collection gap.
