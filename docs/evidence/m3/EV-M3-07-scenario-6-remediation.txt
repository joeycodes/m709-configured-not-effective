### note: the remediation is the real fix against the baseline. In the baseline the identity (and its backing service principal) exists, so a token is always obtainable -- inert without a role, but present. Removing the identity deletes the service principal, so the token endpoint can no longer issue a credential at all. This is prevention at the source, not detection, and not a role change (revoking a role does not match the baseline, which already had no role).

### note: after the identity removal the token endpoint no longer returns an access_token: the JSON has no such key (KeyError), so TOKEN is empty (token_len 0), and the ARM call with an empty bearer returns 401. Compare the first run (EV-M3-07-scenario-6-first-run), where the identical command produced token_len 2144 and a 403 (baseline) / 200 (misconfigured). The attack surface is gone at the source: there is no credential to steal, independent of any RBAC role. This is why removing the service principal -- not revoking a role -- is the remediation that matches the baseline.
