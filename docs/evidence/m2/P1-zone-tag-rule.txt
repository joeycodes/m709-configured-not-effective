### 2026-10-13
### test: the zone-tag rule (infra/policy/zone_tag.rego) rejects every taggable resource that lacks a valid zone tag, and passes once the configuration carries one
### note: run locally against a plan of the lab while it was destroyed, so every resource is planned for creation (the fresh-build case CI meets after each nightly destroy). Plan generated with the author's account: terraform plan -out="$TMPDIR/tfplan"; terraform show -json "$TMPDIR/tfplan" > "$TMPDIR/plan.json". The plan stays outside the repository; *.tfplan, tfplan and plan.json are also in .gitignore.
### note: the rule selects resources by schema, not by a list of types: any planned resource whose state has a tags attribute (or whose tags are unknown at plan time) is checked; only azurerm_resource_group is exempt. (c) shows which types that selects: the six zone-bearing types plus the resource group.
### note: (b) and (d) bracket the change that added the tags. 29 failures in (b), one per taggable resource; the same 29 resources carry a zone in (d). The zone values are derived from the for_each key or value that also places each resource (each.key, each.value.vnet) or written once for the single hub and on-premises resources; the rule checks that a zone is present and valid, not that it is the right one, so (d) was read by eye.
### note: between (b) and (d) the rule was reordered so that a destroyed resource (after = null) is excluded before its attributes are read; results are unchanged. conftest counts each deny rule as one test when nothing fails, hence "2 tests" in (d).
### note: the temporary directory path is shown as $TMPDIR.
