### 2026-10-15
### test: the NVA address rule (infra/policy/nva_ip.rego) rejects a hub NIC that does not hold lab.nva_ip (10.100.2.4) on a statically allocated ip_configuration, including a dynamically allocated one whose address is unknown at plan time
### note: the rule selects azurerm_network_interface.hub (not being destroyed) and requires that some ip_configuration carries private_ip_address == lab.nva_ip and private_ip_address_allocation == "Static". It is written as "cannot show compliance -> deny", so an address absent from `after` (dynamic, or computed) is rejected rather than skipped.
### note: the hub NIC's address is a literal in its own configuration, so unlike the spoke routes' next hops it is known on a fresh build. That is why the next-hop rules (P3) can defer the address to this rule: a next hop taken from the hub NIC is unknown at plan time, but the NIC it is taken from is pinned here to the standard value.
### note: the standard value lives in infra/policy/lab.rego, not in the Terraform configuration. In (c) the NIC's address changes and the spoke routes that reference it would follow it to 10.100.2.5; nothing in the spoke-route checks changes, since their next hops are still unknown references to the hub NIC. Only this rule, comparing against a value held outside the configuration, sees the change.
### note: same plan as P1 (d) to P3, unmodified in (b); (c) and (d) each change the hub NIC's ip_configuration only, as the diffs show. Run locally by the author with conftest 0.71.1; the temporary directory path is shown as $TMPDIR. conftest counts each deny rule as one test: eight rules in four packages (zone_tag 2, pip_tier0 2, spoke_routes 3, nva_ip 1).
