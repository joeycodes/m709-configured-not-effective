### (d) the fix
### note: both representations of "no public IP" are accepted. The rule also changes from "has a value and the value is wrong" to fail closed: a configuration where the field is absent altogether, rather than null or "", is now denied instead of skipped. A unit test for the deployed shape is added (tier-0 NIC, public_ip_address_id "", no deny expected).
### cmd: git diff 531a4d0 d2d20ab -- infra/policy/pip_tier0.rego   (changed lines only)

-	cfg.public_ip_address_id != null
+	not cfg.public_ip_address_id in no_pip_values

+no_pip_values = {null, ""}

### result
### A rule that passed its unit tests, CI (P6) and a negative test (P7) gave a false positive on the first plan taken with the lab deployed. The rules depend on the shape of the plan as well as on its content, and that shape changes with deployment state: the same absent value is null on a fresh build and "" once deployed. A rule tested in one shape is unproven in the other. With main applied, every pull request opened while the lab was up would have failed the required plan check on this finding.
