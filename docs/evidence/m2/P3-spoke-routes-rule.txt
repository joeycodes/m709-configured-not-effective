### note: three deny rules, each over the route tables zoned tier0/tier1/tier2 (resource_changes):
###   (1) 0.0.0.0/0 and 10.100.0.0/14 each route to a VirtualAppliance;
###   (2) the table's configuration block exists and every reference in its route expression is the hub NIC (azurerm_network_interface.hub or .hub.private_ip_address), the list being non-empty;
###   (3) any VirtualAppliance route whose next hop is known at plan time names lab.nva_ip (10.100.2.4, infra/policy/lab.rego).
### note: on a fresh build every next hop is unknown (absent from `after`, true in `after_unknown`), because it references the hub NIC before the NIC exists; rule (2) covers that case from the configuration. The hub NIC's own address is checked separately (nva_ip.rego).
### note: `references` lists each reference twice over: once as the attribute (hub.private_ip_address) and once as the resource (hub), and the route block's two routes each contribute both, so the real plan carries four entries.
