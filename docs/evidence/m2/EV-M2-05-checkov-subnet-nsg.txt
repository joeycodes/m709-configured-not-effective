### 2026-10-15
### test: rule 4 (every subnet that can take an NSG has one) is enforced by Checkov's predefined check CKV2_AZURE_31, not by a custom Rego rule; this records that the check fires, at which granularity, and where it can be bypassed
### note: CKV2_AZURE_31 is a graph check on the Terraform source. It follows the reference from azurerm_subnet_network_security_group_association.subnet_id to the subnet, so it needs no resource IDs and is unaffected by a fresh build, where every ID is unknown at plan time. That is the reason this rule sits with Checkov while the route-table association (rule 3d) was moved to the post-deploy effective-route check in W6.
### note: the check is suppressed inline on azurerm_subnet.reserved only (GatewaySubnet, AzureFirewallSubnet: Azure does not accept an NSG on either). It stays active on azurerm_subnet.workload and azurerm_subnet.onprem.
### note: the check proves that an NSG is associated, not what the NSG allows. The NSG's effective rules are verified after deployment (W6).
### note: Checkov 3.3.19, the version pinned in .github/workflows/policy.yml. Run in a scratch copy of infra/ and .checkov.yml ($WORK); the repository was not modified. Each case starts from the committed network.tf and changes only what its diff shows. BC_SKIP_MAPPING=TRUE was set to stop Checkov fetching guideline links from the vendor API, which the network this was run on blocks; it does not change which checks run. Listings of CKV2_AZURE_31 alone are run outside $WORK so that .checkov.yml (quiet: true) does not hide passed and skipped results.
